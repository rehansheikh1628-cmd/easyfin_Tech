Deterministic Architecture

From financial data to structured output.

Follow the step-by-step workflow from file ingestion to validated, usable accounting data. ACCUFEX maintains completely separate pipelines for statement parsing and Tally XML generation.

Workflow 1 In-Depth

Bank Statement PDF → Excel Process

A 6-stage deterministic pipeline from digital PDF ingestion to ClosedXML spreadsheet download.

Open Converter
01
Stage: Ingestion Digital PDF Upload

Upload Statement & Assign Workspace

Select a supported digital bank statement PDF. Assign the file to an authorized Client and Financial Year within your workspace. The server streams the upload securely and calculates an invariant SHA-256 hash to detect duplicate uploads.

Accepted File Type Digital PDF (.pdf)
Security Guard SHA-256 Duplicate Check
Workspace Isolation Client • Financial Year
02
Stage: Geometry Extraction PdfPig Engine

Extract Coordinates & Bounding Boxes

ACCUFEX extracts characters, words, and bounding box geometry directly from the PDF's native font glyphs using PdfPig. Processing occurs entirely in-process on the application server with zero third-party cloud extraction dependencies.

Extraction Engine PdfPig v0.1.16
Cloud Dependency 0 Cloud API Calls
Geometry Extracted X, Y, Width, Height, Glyphs
03
Stage: Deterministic Classification BankDetector • Parsers

Detect Bank & Calibrate Column Geometry

The bank detector evaluates IFSC patterns, bank branding, and table headers to score and select the appropriate calibrated parser (e.g. HDFC-v1, ICICI-v2). Column boundaries are dynamically calibrated from table header intervals. Multi-line descriptions and cross-page transactions (N → N+1) are joined into unified rows.

Calibrated Institutions 8 Banks • 9 Layout Profiles
Narration Joining Multi-line • Cross-page
Detection Method Multi-signal deterministic score
04
Stage: Mathematical Validation TransactionValidationService

Verify Running Balances & Arithmetic Integrity

Every extracted transaction is verified against mathematical balance continuity. The validation engine ensures that each row's previous balance plus credits minus debits exactly equals its new balance. The global equation Opening Balance + ΣCredits - ΣDebits = Closing Balance is verified against statement summary figures.

Validation Rule 1 Prev + Cr - Dr = Current Balance
Validation Rule 2 Opening + ΣCr - ΣDr = Closing
Discrepancy Action Flagged for Review
05
Stage: Interactive Review Review Grid • Audit Store

Inspect Flags & Apply Auditable Corrections

Transactions requiring inspection are displayed in the high-density in-browser review table. Users can search by narration, filter by debit/credit, and correct values if necessary. All modifications are recorded in an auditable sidecar store, preserving the pristine raw extraction.

Original Data Pristine snapshot preserved
Audit Persistence Sidecar correction store
Real-Time Recalculation Immediate running balance update
06
Stage: Output ClosedXML Spreadsheet

Export Formula-Ready ClosedXML Excel (.xlsx)

Download a cleanly formatted Microsoft Excel workbook generated via ClosedXML. Financial values are true numeric floating-point numbers, dates are native Excel serial dates, and references (UTR, NEFT, cheque numbers) are formatted cleanly. Includes locked header freeze panes and a summary sheet.

Format Generated Microsoft Excel (.xlsx)
Number Formatting Numeric Currency (#,##0.00)
Compatibility Excel 2016+, M365, LibreOffice

Digital PDF Requirement • OCR Limitations

ACCUFEX's standard parser workflow processes native digital PDFs with selectable text layers. Scanned PDFs, camera photos, passbook printouts, and image-only documents require Optical Character Recognition (OCR) and are not currently included in the standard digital-PDF parser workflow.

Workflow 2 In-Depth

Excel → Tally XML Process

A 7-stage accounting pipeline transforming standardized Excel spreadsheets into import-ready Tally XML vouchers.

Open Excel → Tally
01
Stage: Preparation Template Acquisition

Download Official ACCUFEX Template (.xlsm)

Download the official, standardized ACCUFEX Excel template directly from the application. The workbook contains pre-configured columns matching the required schema for Tally voucher generation.

Template Format Macro-Enabled Excel (.xlsm)
Required Columns Date, Particulars, Debit, Credit, Ledger
Source of Truth ACCUFEX Official Template
02
Stage: Data Entry Transaction Mapping

Fill Transaction Data & Ledger Names

Enter or paste transaction rows into the template. Specify the bank or cash ledger name, counter-ledger account, transaction amounts, and reference details. The template maintains clear separation between debit and credit columns.

Supported Sources Any bank, cash, or ERP export
Ledger Assignment Direct counter-ledger mapping
Data Integrity Separate Debit & Credit columns
03
Stage: Upload Workbook Ingestion

Upload Completed Workbook to ACCUFEX

Upload the completed .xlsm workbook to the secure /excel-to-tally endpoint. ACCUFEX reads the spreadsheet using ClosedXmlExcelReaderService with strict workbook validation.

Accepted Extensions .xlsm, .xlsx
File Reader ClosedXmlExcelReaderService
Validation Engine ExcelToTallyValidationService
04
Stage: Schema Verification Rules Engine

Validate Column Headers, Dates & Balances

The server-side validation service performs strict checks: confirms all required headers exist, validates date formats, verifies that positive amounts are present, checks that debit and credit amounts do not conflict on the same row, and confirms that ledger names are populated.

Header Validation Exact required schema verification
Amount Validation Strict positive non-zero checks
Error Reporting Structured error list with row numbers
05
Stage: Preview Transaction Review

Preview Transactions & Voucher Classifications

Inspect the validated transaction dataset in the web preview grid. Review total debit and credit amounts, transaction counts, and verify that voucher types match expected accounting directions.

Debit Direction Payment Voucher
Credit Direction Receipt Voucher
Summary Check Total Debit • Total Credit
06
Stage: Generation TallyXmlGenerator

Generate Canonical Tally XML Vouchers

TallyXmlGenerator constructs the standard Tally XML envelope (<ENVELOPE><BODY><IMPORTDATA>...). Every voucher is generated with correct ledger entries, GUID identifiers, date stamps in YYYYMMDD format, and balanced ledger postings.

XML Standard Tally Canonical XML Schema
Date Format YYYYMMDD
Voucher Types Payment • Receipt
07
Stage: Completion Import into Tally

Download XML & Import into TallyPrime

Download the resulting .xml file. In TallyPrime or Tally.ERP 9, navigate to Import → Transactions, select the downloaded XML file, and import all vouchers directly into your company ledgers in one click.

File Type XML (.xml)
Tally Target TallyPrime • Tally.ERP 9
Import Method Import → Transactions
Workflow 3 • Roadmap

Bills & Invoices → Excel

A planned future workflow designed to extract and normalize vendor bills, sales invoices, and GST metadata into structured spreadsheets.

Engineering Status: In Research

Bills and invoices present fundamentally different layout challenges from bank statements: variable vendor invoice structures, multi-rate tax breakdowns, line-item quantity grids, and optical scans.

ACCUFEX's engineering principle is Accuracy > Feature Count. We do not release or advertise features that rely on speculative or probabilistic guessing. The Bills & Invoices workflow is currently undergoing architectural evaluation and is not yet available in production.

Current production availability: Workflows 1 (Bank Statement PDF → Excel) and 2 (Excel → Tally XML) are fully active and validated.
Core Philosophy

The Validation Difference: Why ACCUFEX Verifies Every Rupee

01

Text Extraction is Not Accounting

Tools that simply extract text from PDFs often miss decimal commas, split descriptions across phantom rows, or swap debit and credit columns. ACCUFEX requires every transaction to reconcile arithmetically against running balances.

02

Pristine Snapshots & Sidecar Audits

When corrections are made in the review grid, ACCUFEX does not mutate raw extraction records. Edits are persisted in an immutable sidecar audit trail, preserving full evidentiary provenance for Chartered Accountants.

03

Zero Cloud Extraction Dependencies

PdfPig extracts character geometry directly in-process on the application server. Financial statement documents are never transmitted to third-party AI vision APIs or unvetted external services.

Storage & Privacy

What Happens to Your Files in ACCUFEX

Private Sandboxed Storage

Uploaded statement PDFs are stored in sandboxed private disk directories outside public web folders, protected against path-traversal vulnerabilities.

Strict Authorization Chains

Every access request verifies ownership from the authenticated session down to the file and transaction: User → Client → FileRecord → Transaction.

Workspace Isolation

Statement files and transaction datasets are strictly isolated by Client and Financial Year. Cross-account inspection is blocked at the database and API layers.
