Deterministic Architecture

From financial data to structured output.

Step-by-step workflows from file ingestion to validated accounting data. ACCUFEX maintains distinct pipelines for statement parsing and Tally XML generation.

Workflow 1 In-Depth

Bank Statement PDF → Excel Process

A 6-stage deterministic pipeline from digital PDF ingestion to ClosedXML spreadsheet download.

Open Converter
01
Stage: Ingestion Digital PDF Upload

Upload Statement & Assign Workspace

Upload a digital bank statement PDF and assign it to an authorized Client and Financial Year. Files are streamed securely and deduplicated via invariant SHA-256 hashing.

File: Digital PDF (.pdf) Security: SHA-256 Deduplication Isolation: Client • FY Sandboxed
02
Stage: Geometry Extraction PdfPig Engine

Extract Coordinates & Bounding Boxes

PdfPig extracts character glyphs, words, and bounding box geometry directly in-process on the application server with zero third-party cloud dependencies.

Engine: PdfPig v0.1.16 Privacy: 0 Cloud API Calls Geometry: X, Y, Width, Height
03
Stage: Deterministic Classification BankDetector • Parsers

Detect Bank & Calibrate Column Geometry

The detector scores IFSC codes, branch patterns, and table headers to select the calibrated parser. Column boundaries are dynamically aligned, joining multi-line narrations and cross-page transactions.

Coverage: 8 Banks • 9 Profiles Reconstruction: Multi-line & Cross-page Method: Deterministic Scoring
04
Stage: Mathematical Validation TransactionValidationService

Verify Running Balances & Arithmetic Integrity

Every row is verified against running balance continuity (Prev + Cr - Dr = Current Balance) and reconciled against global summary figures (Opening + ΣCr - ΣDr = Closing).

Check: Row Running Balances Reconciliation: Opening → Closing Checksum Action: Discrepancies Flagged
05
Stage: Interactive Review Review Grid • Audit Store

Inspect Flags & Apply Auditable Corrections

Flagged transactions can be inspected and edited directly in the browser review table. Corrections are saved to an immutable sidecar store, preserving pristine extraction snapshots.

Integrity: Pristine Snapshot Preserved Audit: Sidecar Change Log Live Math: Immediate Recalculation
06
Stage: Output ClosedXML Spreadsheet

Export Formula-Ready ClosedXML Excel (.xlsx)

Download a cleanly formatted Microsoft Excel workbook with numeric decimal values, native Excel dates, locked header freeze panes, and preserved alphanumeric references.

Format: Microsoft Excel (.xlsx) Numbers: Decimals (#,##0.00) Compatibility: Excel 2016+, M365

Digital PDF Requirement • OCR Limitations

ACCUFEX's standard parser workflow processes native digital PDFs with selectable text layers. Scanned PDFs, camera photos, passbook printouts, and image-only documents require Optical Character Recognition (OCR) and are not currently included in the standard digital-PDF parser workflow.

Workflow 2 In-Depth

Excel → Tally XML Process

A 7-stage accounting pipeline transforming standardized Excel spreadsheets into import-ready Tally XML vouchers.

Open Excel → Tally
01
Stage: Preparation Template Acquisition

Download Official ACCUFEX Template (.xlsm)

Download the official, standardized ACCUFEX template with pre-configured column headers matching canonical Tally XML voucher schemas.

Template: Macro-Enabled Excel (.xlsm) Columns: Date, Particulars, Debit, Credit, Ledger
02
Stage: Data Entry Transaction Mapping

Fill Transaction Data & Ledger Names

Enter or paste transaction rows into the template. Specify bank/cash ledgers, counter-ledgers, and distinct debit and credit columns.

Sources: Any bank, cash, or ERP export Mapping: Counter-ledger account assignment
03
Stage: Upload Workbook Ingestion

Upload Completed Workbook to ACCUFEX

Upload the .xlsm or .xlsx workbook. ClosedXmlExcelReaderService parses and reads spreadsheet contents strictly as passive tabular data.

Formats: .xlsm, .xlsx Engine: ClosedXmlExcelReaderService
04
Stage: Schema Verification Rules Engine

Validate Column Headers, Dates & Balances

Server-side validation confirms required headers exist, validates dates, checks for positive non-zero amounts, and verifies debit/credit integrity.

Headers: Schema Verification Amounts: Positive non-zero checks Reporting: Row-level diagnostic errors
05
Stage: Preview Transaction Review

Preview Transactions & Voucher Classifications

Inspect the validated transaction dataset in the web preview grid. Review total debit and credit amounts, transaction counts, and voucher directions.

Debits: Payment Vouchers Credits: Receipt Vouchers Totals: Debit • Credit Balance Check
06
Stage: Generation TallyXmlGenerator

Generate Canonical Tally XML Vouchers

TallyXmlGenerator constructs the standard Tally XML envelope with balanced ledger postings, GUID identifiers, and YYYYMMDD date stamps.

Standard: Tally Canonical XML Dates: YYYYMMDD Vouchers: Payment • Receipt
07
Stage: Completion Import into Tally

Download XML & Import into TallyPrime

Download the generated .xml file and import via TallyPrime or Tally.ERP 9 (Import → Transactions) directly into your company ledgers.

File: XML (.xml) Target: TallyPrime • Tally.ERP 9 Import: Import → Transactions

Institutional Foundations

Engineered for Audit Compliance & Data Security

Disciplined technical boundaries ensuring precision and privacy.

01

Mathematical Balance Verification

Every transaction reconciles arithmetically against running balances (Prev + Cr - Dr = Balance). Discrepancies are highlighted rather than silenced.

02

Immutable Sidecar Auditing

Raw extracted transactions remain permanently immutable. Corrections are tracked in an evidentiary sidecar log for audit compliance.

03

Zero Cloud Extraction

PdfPig extracts character geometry in-process on the application server. Financial files are never sent to third-party AI vision APIs.

04

Private Sandboxed Storage

Files and records are strictly isolated by Client and Financial Year outside public web roots with session-level authorization.
